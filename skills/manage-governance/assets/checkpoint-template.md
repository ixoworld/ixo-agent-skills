# Governance checkpoint

Working coordination record; not an authoritative status or a service payload. Omit unknown identifiers or mark them unknown. Never include secret keys or live bearer tokens.

- Stable proposal reference / temporary Draft label:
- Intent verbatim and accepted scope:
- Current user / oracle / acting-for identity; network:
- Entity DID; governing group; exact room/Topic and revision:
- Visibility, permitted readers and persistence receipt (or unsaved):
- Proposal version / CID; resolution / Flow / message payload CIDs:
- Submissions: chain ID, DAO core, module, proposal ID, transaction/finality evidence for each version:
- Module compatibility: selected kind/address and per-module versions; current pre-propose route; approval-module/approval ID and later actual voting proposal linkage; option map/winning option evidence; veto/pause/activity state; requested auto-vote and actual ballot receipt:
- Observed decision status, source and observation time:
- Authority/proof references, expiry/revocation source; validation still needed:
- Execution by grant/node: run, operation, raw status, receipt/read-back, reserved/consumed budget or unknown:
- Claims: entity/collection/claim IDs, content/evidence versions, submission status and source:
- Evaluations: rubric/version, evaluator/authority, result reference, recommendation versus authoritative decision:
- Outcomes: criteria, observations, uncertainty, unresolved challenges and review event/date:
- Existing user authorisations: exact action/version/audience and source; native confirmation still pending if any:
- Current blockers: dependent step, missing fact/capability, responsible actor, what resolving it unlocks:
- Next useful action and actor:
- Active watch: ID/receipt, scope, recipient authority, expiry/cancellation (or no watch):
- Supersedes / superseded by / correction links:

Before reuse, refresh evidence and permissions relevant to the next action. Do not turn this checkpoint's labels into chain or Topic state.
