# Localisation and contextual usability

Original IXO supporting reference. Select only combinations relevant to the
named users and task. An empty locale specification is a missing input, not
permission to assume English or the reviewer's device.

- Language/locale: intended language variant, terminology, register, input methods,
  text expansion, script direction, names/addresses, dates/numbers/currency and
  code-switching. Require fluent domain review where machine translation cannot
  establish correctness.
- Culture/context: expectations, imagery, examples, trust/consent language and
  local task conventions. Ask local specialists about interpretation rather than
  inferring one culture from a language code.
- Device/connectivity: representative screen/input, low-end hardware, bandwidth,
  intermittent/offline recovery and data-entry constraints.
- Assistive technology: selected screen reader/browser/OS, language pronunciation,
  focus order, zoom/reflow and alternative input. Include users with relevant
  access needs or explain the limitation if that participation is unavailable.

For each selected combination record the same user task, setup, expected
completion/error recovery, observable failure, evidence and reviewer language/
domain/access expertise. Re-run the finite matrix on the changed build in follow-up.
A translated string or automated scan alone cannot establish local usability.
